# Бортовик: сервер кошелька и оплаты (ЮKassa)

Один файл `server.js`, без внешних зависимостей. Нужен Node.js 22 или новее.

## Что умеет

| Адрес | Что делает |
|---|---|
| `GET /api/wallet` | номер кошелька, баланс, история операций и заказов |
| `POST /api/topup` | пополнение: `{amount, method, email}` → ссылка на оплату ЮKassa |
| `POST /api/orders` | заказ: `{items:[{id,qty}], delivery, vin, useWallet, method, email}`. Часть суммы списывается с баланса, остаток уходит в ЮKassa |
| `POST /api/orders/cancel` | отмена оплаченного заказа, деньги возвращаются на баланс |
| `POST /api/transfer` | перевод другому кошельку магазина: `{toWallet, amount, note}` |
| `POST /api/withdraw` | вывод на кошелёк ЮMoney через выплаты ЮKassa: `{amount, account}` |
| `POST /api/yookassa/webhook` | уведомления ЮKassa о платежах и выплатах |

Способы оплаты (`method`): `yoo_money`, `sbp`, `sberbank` (SberPay), `tinkoff_bank` (T-Pay), `bank_card`.

## Как устроен учёт

- Суммы хранятся в копейках, баланс считается как сумма записей журнала `ledger`.
- Цены берутся только из каталога на сервере, сумма из браузера не принимается.
- Повторное уведомление ЮKassa не зачислит деньги дважды.
- Статус платежа сервер перепроверяет запросом к ЮKassa, телу уведомления не доверяет.
- При смешанной оплате часть с баланса резервируется, а при отмене платежа резерв снимается.

## Запуск

```bash
YK_SHOP_ID=123456 \
YK_SECRET_KEY=live_xxx \
RETURN_URL=https://ваш-сайт.ru/#wallet \
node server.js
```

Дополнительные переменные: `PORT`, `DB_PATH`, `YK_RECEIPTS=1` (чеки 54-ФЗ через ЮKassa), `YK_PAYOUT_AGENT_ID` и `YK_PAYOUT_SECRET` (выплаты), `CORS_ORIGIN`.

В личном кабинете ЮKassa укажите адрес уведомлений `https://ваш-сайт.ru/api/yookassa/webhook` и включите события `payment.succeeded`, `payment.canceled`, `payout.succeeded`, `payout.canceled`.

## Что сделать перед запуском

1. **Авторизация.** Сейчас пользователь определяется заголовком `X-User-Id`. Это заглушка: замените её на вход по телефону или почте с сессиями.
2. **Договор с ЮKassa** на ИП, ООО или самозанятого. Выплаты на кошельки подключаются отдельно.
3. **Правовая часть.** Хранение денег пользователей на балансе и переводы между ними могут подпадать под регулирование платёжных услуг (161-ФЗ). Безопасный вариант: считать баланс авансом за товары магазина, а переводы оформить как зачёт между покупателями и партнёрами-установщиками по договору. Обсудите схему с юристом и ЮKassa до запуска.
4. **Чеки.** При смешанной оплате долю с баланса правильнее проводить как зачёт предоплаты. Уточните это с бухгалтером.
5. Перенесите базу на PostgreSQL при росте нагрузки, логика журнала та же.
